# Persinder

**Персональный индексатор** — поисковый движок для персональной базы знаний.

## Описание

Persinder индексирует информацию из различных источников:

- **Obsidian** — заметки и связи между ними
- **Local files** — PDF, DOCX, изображения, DjVu, ZIP-архивы
- **Web** — веб-страницы и онлайн-материалы

## Возможности поиска

- **Поиск по совпадению слов** — классический полнотекстовый поиск
- **Поиск по тэгам** — фильтрация и навигация по меткам
- **Семантический поиск** — поиск по смыслу, а не только по точным словам

## Авто-каталогизирование

Persinder ведёт автоматическое каталогизирование:

- закладок
- книг
- статей
- CD-архивов

## Платформы

- **Десктоп:** Windows и Linux
- **Мобильные:** Android (позже)

## Индексация при старте

Индекс строится **от файлов, а не от журнала** (D25). `./run.sh` запускает
`persinder serve --reindex`, и при каждом старте:

1. читаются полные каталоги всех областей — только имена файлов, без хэшей;
2. состав сверяется с журналом **по именам**: новые файлы индексируются,
   удалённые убираются из индекса (документ, сырой текст, сайдкар);
3. очередь эмбеддингов очищается, и **в фоне** (не более 5% CPU) файлы, уже
   проиндексированные, проходят через обычный конвейер: неизменённые он узнаёт
   по уже хранящемуся хэшу текста (`content_hash`) и не трогает, изменённые —
   переиндексирует;
4. дальше работает обычный watcher по `(size, mtime)`.

Журнал при этом не сбрасывается, поэтому старт не перечитывает библиотеку
целиком. Инкрементальный старт без сверки хэшей — `./run.sh --no-reindex`
(или `NO_REINDEX=1`). Предел CPU для сверки — `PERSINDER_REINDEX_CPU_LIMIT`
(по умолчанию 5), для эмбеддингов — `PERSINDER_CPU_LIMIT`.

## Разработка

Ядро — на стандартной библиотеке Python; единственная обязательная внешняя
зависимость — `onnxruntime` (+ `tokenizers`): у него официальные колеса для
Windows/Linux/macOS, поэтому Persinder ставится и работает «из коробки», без
Docker. Сама модель эмбеддингов (~120 МБ) — не в пакете, а управляется явно:
`persinder model install`.

```bash
# тесты
PYTHONPATH=src python3 -m unittest discover -s tests

# единый сервис: HTTP (приём+поиск) + watcher + эмбеддинги; Ctrl+C — стоп
PYTHONPATH=src python3 -m persinder serve --config persinder.yaml --home ~/.persinder

# только эмбеддинги по требованию: очередь → векторы → сайдкары (модуль 2)
PYTHONPATH=src python3 -m persinder embed --home ~/.persinder

# модель эмбеддингов: установка и переключение (D24)
PYTHONPATH=src python3 -m persinder model install e5-small-int8-v1   # веса + миграция в очередь
PYTHONPATH=src python3 -m persinder embed --background               # разобрать очередь до пустой
PYTHONPATH=src python3 -m persinder model use e5-small-int8-v1       # переключить поиск

# семантический поиск (модуль 3): морфология + семантика.
# Идёт через запущенный serve (GET /search) и видит его модели и скоупы;
# --local — искать в БД профиля без сервера.
PYTHONPATH=src python3 -m persinder search "коты сидят" --limit 10

# только семантические хиты с косинусом не ниже порога (порог подбирается
# под свои данные: короткие тексты дают заметно ниже, чем длинные чанки)
# и отдельные лимиты слоёв: морфология 5, семантика 50
PYTHONPATH=src python3 -m persinder search "кузя" \
  --morph-limit 5 --semantic-limit 50 --min-score 0.85

# ANN-индекс USearch: пересобрать из таблицы (холодный старт/рассинхрон)
PYTHONPATH=src python3 -m persinder ann rebuild

# проверка
curl -s localhost:8756/health
curl -s -X POST localhost:8756/ingest \
  -H 'Content-Type: application/json' \
  -d '{"filename":"note.md","area":"personal","text":"Привет мир"}'
```

Реализованы **модуль 1** (`ingest` — приём текста, морфологический слой FTS5,
журнал вызовов, инлайн-удаление), **модуль 2** (`embed` — воркер очереди:
текст → векторы → сайдкары, реестр моделей и явный модель-менеджмент) и
**модуль 3** (`vectorindex` — семантический поиск: ANN USearch `home/ann/`
поверх таблицы `embeddings`, точный скан таблицы как фолбэк).
Эмбеддер — реальная модель e5-small (ONNX INT8, `persinder model install`)
или детерминированная заглушка (`placeholder-v1`, встроена). У файла живут
сайдкары нескольких моделей сразу (по подпапке на модель): при установке новой
модели миграция стартует в фоне, поиск остаётся на старой до явного
`persinder model use`; удаление `persinder model remove` убирает веса, все
сайдкары и векторы модели в один момент. Векторный поиск идёт активной
поисковой моделью (`model use`), в ответе `/search` семантические хиты —
отдельным полем `semantic_hits` рядом с `hits`. У каждого хита есть источник —
`area`, `source_path` (полный путь на диске) и `filename`; у виртуальных
документов `source_path` пуст. Поле `context` — текст чанка вместе с тремя
строками до и тремя после (по сырому тексту документа; `null`, если текст
недоступен). Векторный поиск идёт по
USearch-индексу (mmap-файл на модель, `persinder ann rebuild` пересобирает);
единое ранжирование (D16) — следующий шаг. Карта и интерфейсы — в
`docs/modules.md`.

## Сценарии deploy

Проверка и сборка одной командой — `./deploy.sh` (обёртка над
`deploy/deploy.py`, подробности в `--list`):

```bash
./deploy.sh test    # все тесты: pytest (tests/) + vitest (web/)
./deploy.sh build   # веб-клиент (npm run build:static) + wheel в dist/
```

Python для тестов/сборки скрипт выбирает сам: venv проекта (`.venv`), иначе
системный `python3` (можно переопределить: `PERSINDER_DEPLOY_PYTHON=...`).

## Веб-интерфейс

Собранный клиент лежит в `src/persinder/api/static/` и раздаётся тем же
`persinder serve`; Node.js на машине пользователя не нужен:

```bash
./run.sh        # или: persinder serve --config persinder.yaml
# открыть http://127.0.0.1:8756/
```

Сервер отдаёт `/`, `/assets/…` и маршруты приложения (`/settings`), а API
(`/search`, `/health`, `/ingest`) работает как раньше.

Пересборка интерфейса — только для разработчиков, в `web/`:

```bash
cd web
npm install --no-bin-links
npm run build:static   # соберёт и заменит src/persinder/api/static/
```

Подробности — в [`web/README.md`](web/README.md).
