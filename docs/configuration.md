# Конфигурация

Справочник по YAML-конфигу Persinder: области индексации, watcher и
глобальные переключатели. Источник правды — `persinder.sources.config`
(разбор и валидация) и `persinder.sources.models` (`AreaConfig`,
`WatchConfig`).

PyYAML — опциональная зависимость (extra `config`); без неё загрузка конфига
падает с понятной ошибкой.

## Где ищется конфиг

1. `--config <путь>` (у `serve` и `watch`);
2. иначе — `persinder.yaml` / `persinder.yml` в текущем каталоге;
3. иначе — `persinder.yaml` / `persinder.yml` в `home` (`--home`, по
   умолчанию `~/.persinder`).

Если конфиг не найден, `serve` деградирует до HTTP-only — приём и поиск по
тому, что уже в базе, без watcher и эмбеддингов; `watch` требует `--config`.

## Полный пример

```yaml
semantic: true              # false — выключить эмбеддинги целиком
search:
  min_score: 0.85           # порог косинуса семантического слоя (null — без порога)
areas:
  - path: ~/Obsidian/Personal
    role: personal
    recursive: true
    formats: [structure-text, text]     # классы или конкретные форматы
    embedding_model: e5-small-int8-v1   # модель только для этой папки (null — глобальная)
    semantic: true                      # false — папка без эмбеддингов
  - path: ~/Library/Books
    role: foreign
    formats: [pub-formats, structure-text]
watch:
  poll_interval: 30         # сек между сканами
  debounce: 2               # сек — ждать после mtime, чтобы не читать полуфайл
  ignore:                   # дополнительно к встроенным паттернам
    - "**/drafts/**"
```

Минимально: `areas` с `path`, `role` и непустым `formats` (пустой список —
папка пропускается, ничего не индексируется).

## Верхний уровень

| Ключ | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `semantic` | bool | `true` | `false` — не ставить эмбеддинги нигде (морфология продолжает работать) |
| `search` | mapping | — | Блок настроек поиска; см. `search.min_score` |
| `areas` | list | — | Области индексации; **обязателен непустой список** |
| `watch` | mapping | — | Настройки watcher'а; см. ниже |

`search.min_score` — число (или `null`), порог косинуса семантического слоя по
умолчанию. Должно быть конечным (не `NaN`/бесконечность). Сервер применяет
его, когда CLI/веб не передали свой `min_score`. Абсолютное значение зависит
от модели и корпуса — подбирается под данные, а не считается вероятностью.

## `areas[]` — области индексации

Каждый элемент — одна локальная папка с назначением:

| Ключ | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `path` | строка | — | Путь к папке; обязателен, должен существовать |
| `role` | `personal` \| `foreign` \| `web` | — | Роль папки; обязательна |
| `recursive` | bool | `true` | Обходить вложенные каталоги |
| `formats` | список строк | `[]` | Что индексировать: классы и/или конкретные форматы; пусто — папка пропускается |
| `embedding_model` | строка \| null | `null` | Модель эмбеддингов именно для папки (`null` — глобальная из `models.json`) |
| `semantic` | bool | `true` | `false` — папка без эмбеддингов (только морфология) |

**Путь.** `~` раскрывается. Относительный путь считается от каталога, где
лежит сам конфиг (не от CWD процесса) — профиль переносим между машинами.
Если каталога нет — ошибка конфига, а не молчаливый пропуск.

**Роли:**
- `personal` — личные заметки (группа «Личное»);
- `foreign` — копии чужого: книги, статьи (группа «Локальное»);
- `web` — закладки/web-архив (наполняется отдельным проектом-скрапером).

## `watch` — watcher

| Ключ | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `poll_interval` | число > 0 | `30` | Секунд между сканами областей |
| `debounce` | число ≥ 0 | `2` | Секунд после изменения mtime — чтобы не читать недописанный файл |
| `ignore` | список строк | `[]` | Дополнительные glob-паттерны (в дополнение к встроенным) |

`semantic` и `min_score` берутся только с **верхнего уровня** конфига:
внутри блока `watch` они игнорируются (поле в `WatchConfig` есть, но
перезаписывается при загрузке).

## Форматы: классы и конкретные форматы

`formats` области — белый список. В нём можно писать:

- **имя класса** — включается весь класс:
  `text`, `structure-text`, `pub-formats`, `archive`, `ocr`, `code`,
  `science`;
- **имя конкретного формата** — включается только он:
  `markdown`, `html`, `mhtml`, `pdf`, `epub`, `fb2`, `rtf`, `chm`, …

Пример: `[structure-text]` индексирует md + html + mhtml, а `[markdown]` —
только Markdown. Классы `ocr`, `code`, `science` зарезервированы под будущие
экстракторы: имя валидно в конфиге, но файлы таких классов сейчас не
индексируются.

Если реестр форматов известен (обычный запуск), неизвестное имя в `formats`
— ошибка конфига со списком доступных. Пустой `formats` — область
пропускается целиком (например, папка только для хранения, не для индекса).

**Контейнеры.** `archive` — zip, 7z (extra `7z`), tar/tar.gz/tgz/tar.bz2/
tar.xz, rar (extra `rar` + внешний unrar/7z/bsdtar): каждая запись становится
отдельным документом. Вложенные архивы раскрываются рекурсивно (лимит
`ARCHIVE_MAX_DEPTH`, по умолчанию 4). Полный путь части
(`folder/a.zip/folder/b.zip/x.pdf`) сохраняется разбором: файл-контейнер +
цепочка записей в `document_sources`.

## Семантика и модели

- верхний `semantic: false` — эмбеддинги не ставятся нигде;
- `semantic: false` у области — только для неё, остальные папки живут как
  обычно;
- `embedding_model` у области — установленная модель для этой папки;
  по умолчанию глобальная из `models.json`.

Поиск собирает **все активные модели**: текущую глобальную и модели из
конфига папок. Модель ищет только там, где ею индексировали (плюс виртуальные
документы для глобальной); папка со своей моделью исключается из поиска
глобальной, даже если от неё остались старые эмбеддинги. Модель активна по
факту настройки, даже пока папка не проиндексирована полностью.

> `semantic: false` **не** отключает запись сырого текста в `pending_texts`
> (это кэш поиска, D26): текст нужен `/context` и виртуальным документам
> (web/вставка), пишется при индексации и при дубликате по хэшу. Опции «не
> хранить текст для папки» сейчас нет (планируется `is_cachable`, D27).

## Встроенные ignore-паттерны

Не индексируются независимо от `watch.ignore` (служебное и производное):

- `.obsidian/` — служебные данные Obsidian;
- `.persinder/` — сайдкары Persinder;
- `.stfolder/` — служебная папка Syncthing;
- `*.sync-conflict-*` — конфликтные копии Syncthing;
- `.syncthing.*.tmp` — временные файлы Syncthing (пишет и переименовывает).

## Ошибки конфига

Загрузка падает с `ConfigError` (текст указывает ключ), если:

- конфиг не найден или битый YAML;
- верхний уровень — не mapping;
- `semantic` — не bool; `areas` — не список или пустой;
- у области нет/пустой `path`, каталог не существует;
- `role` неизвестна; `recursive` — не bool;
- `formats` — не список непустых строк; имя неизвестно реестру;
- `embedding_model` — непустая строка или `null`; модель не установлена при
  включённой семантике;
- `search.min_score` — не число или не конечное число;
- `watch.poll_interval` ≤ 0; `watch.debounce` < 0; `watch.ignore` — не список
  строк.

## Связанные файлы и переменные

**`models.json`** (в `home`) — активные модели профиля: `embedding` (что
считает векторы) и `search` (чем искать). Управляется командами
`persinder model install|use`, в YAML не задаётся. `embedding_model` в
конфиге папки должен быть среди установленных моделей.

**Раскладка `home`** (по умолчанию `~/.persinder`):

| Путь | Что это |
|---|---|
| `persinder.db` | база: документы, чанки, источники, очередь, эмбеддинги |
| `pending_texts/` | кэш сырого текста: `/context` и воркер эмбеддингов; живёт, пока есть оригинал (D26) |
| `virtual/` | сайдкары виртуальных документов (web/вставка) |
| `models/<ключ>/` | веса и токенизаторы моделей эмбеддингов |
| `models.json` | активные `embedding`/`search` модели |
| `ann/` | ANN-индексы USearch (производное, пересобирается `ann rebuild`) |
| `ingest.jsonl` | журнал индексации (append-only) |

**Переменные окружения:**

| Переменная | Смысл |
|---|---|
| `PERSINDER_EMBED_WORKERS` | число параллельных мини-батчей эмбеддингов (по умолчанию ~половина ядер, не больше 4) |
| `PERSINDER_CPU_LIMIT` | предел CPU для эмбеддингов, % (по умолчанию не задан — без ограничения) |
| `PERSINDER_REINDEX_CPU_LIMIT` | предел CPU для фоновой переиндексации, % (по умолчанию 5) |

**Параметры `Settings`** (не в YAML): `home`, `host`, `port` задаются
флагами CLI (`--home`, `--host`, `--port`). `chunk_size`/`chunk_overlap`
(по умолчанию 1200/200) — поля `Settings`, отдельного ключа конфига у них нет.
